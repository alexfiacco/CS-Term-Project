1 · Who's coming

Remove someone, with a check first

What the code does today. The host's × on a face removes on the first tap, no confirm (iPhone model.removeSeat, web removeParticipant). The server deletes the seat and its vote, writes a room line "Sam left the room", and remembers the removal so the link refuses them ("You can't join this room."). The removed phone is not told: it finds out from the next presence ping, which runs every 60s and only while the app is in front, then shows "You've left the room / You were quiet for a while, or the host made space" with a Rejoin button that the server now refuses. So for up to a minute they keep seeing the room, and the screen they get guesses at a reason and offers a door that is locked.

Current · host

The × is 22pt on the face's corner. One tap and Sam is gone. Easy to hit when you meant to tap the face.

Proposed · host taps ×

The app's confirm drawer (the same one as End night). Sam's face and name so the host knows who, one line on what happens. Remove is the one red on the screen. The × keeps its place, with a 44pt tap area.

Proposed · host, after

Sam's seat goes, the count follows ("Start with the 3 here"), and one quiet line says it happened. Everyone else keeps today's softer "Sam left the room" in the chat.

Current · Sam, up to 60s later

Guesses at the reason, and Rejoin leads to "You can't join this room." Same words on iPhone and web.

Proposed · Sam, at once

Says what happened, once. The room's faces with an empty place, the plain sentence, and two ways out. No Rejoin. Lands within a second because the room already broadcasts the roster change.

Proposed · Sam as a link guest

No account, no Montage to go back to, so the way out is to run your own night. The quiet-sweep case keeps its own screen ("You stepped away" with Rejoin), since that one really can rejoin.

Building it

  • Confirm: iPhone RoomScreen.swift seats(): the × sets a pending seat and opens .confirmDrawer(item:); web TheaterRoom.tsx Seat onRemove goes through askConfirm (lib/confirm.ts), as End night does. × hit area to 44 on both (.mnr-seat-x, SeatView).
  • Telling Sam at once: the roster broadcast already fires (broadcastTheater(id, "roster")). On each roster load, a phone that held a seat and no longer finds it asks the ping, and the ping answers { present: false, removed: true } when removedFromRoom matches (app/api/theater/ping, lib/theater.ts). That splits "removed" from "swept for being quiet", which today share one screen. iPhone RoomModel.ping / load, web the same in TheaterRoom.tsx.
  • Host line: the host sees "You removed Sam." under the seats; the event row is already written (left / removed).
  • No DB change. Removal is already stored (ai_cache theater-removed:<room>). If Sam opens the link later, the invite should show this same screen rather than the generic refusal: a small change in app/api/theater/join to return a removed flag.
  • No push for a removal. Telling someone on their lock screen that they were taken off a list is harsher than the moment needs; they learn it the next time they look at the room.
2 · The invite push

A short title, the who in the body

What the code does today. lib/push-copy.ts, kind movie_night_invite: title "{name} invited you to a movie night", body "{room} · {n} in so far". The name is the display name's first word, else the whole username. The iPhone's NotificationService extension never changes the words; it attaches the inviter's face as the square on the right, and that square takes about 50pt off every line. So a 9-letter username already cuts the title, and the room name, the only thing that says which night, sits in the body.

Current

36 characters into roughly 30 that fit beside the icon, the time and the face.

A · recommended

Movie night invite / JacobHF invited you to Sunday Night Feature. 2 in so far.

B

Sunday Night Feature / JacobHF invited you to movie night. 2 in so far.

A · worst case

A 16-letter username and a 28-letter room name (the longest a room name can be). Over two lines, the count is the part that goes.

A · first to be invited

With nobody else in yet, the body is just who and which night.

B · worst case

The room name as title fits at 28, but two invites in a row read as two room names with no sign they are invites until you read the body.

Why A

  • The title says what this is in three words, at any name length. The face on the right already says who at a glance, so the body only has to say it in words.
  • B puts the room name first, which is nicer once you know the night, but room names are made up ("The Midnight Cultists"), so on the lock screen it reads like a stranger's message.
  • Rule for the body: "{name} invited you to {room}." then " {n} in so far." only when n is 2 or more and the whole body is 70 characters or fewer; otherwise the count drops.
  • Building it: one line in lib/push-copy.ts (movie_night_invite); the welcome tour's sample note in ios/.../WelcomeTour.swift uses the old words and should match. No iPhone build needed for the push itself: the words come from the server. No DB change.
3 · The same invite in Activity

Give the invite room to answer

What the code does today. The invite is a "person" row (Activity.tsx rowLines, ActivityDrawer.swift): line 1 the handle alone, line 2 "invited you to a movie night · Sunday Night Feature · now" with Not tonight pushed onto the end of it, and Join in the right column. Line 2 has about 150pt left after Not tonight, so it cuts to "invited you…" and the room name never shows. The lead is a clapper glyph, so you can't see who either.

Current

Who: a handle. What: "invited you…". Which night: cut off. Two answers squeezed into one line and one pill.

A · recommended

The invite gets a third line for its two answers. The inviter's face (clapper as a small badge), "Jacob invited you" on line 1, the night and the count on line 2, then Join and Not tonight as real pills. It is the one row that asks for a reply, so it can be taller.

B

Keep two lines: the night's name leads, who and when under it, Join in the column. Not tonight moves to a swipe on iPhone and to the room's invite screen. Tidier, but the decline is hidden.

Why A

  • Every answer stays one tap, nothing is hidden, and the row now says who (face and name), which night, and how many are in. B saves 40pt of height but sends "Not tonight" behind a gesture nobody will find on the web.
  • Several rooms from one host stay one row: line 1 "Jacob invited you to 3 movie nights", line 2 the newest night. Once you're in, the pills become the existing "You're in" chip on line 3.
  • Building it: web Activity.tsx (the mn- row: face lead, a new invite layout with an actions line, Join as the cream pill) and globals.css (.act-row invite variant); iPhone ActivityDrawer.swift the same. The face needs actorAvatarUrl on the invite, which the feed already returns for other person rows. No DB change.
