# Faces on notifications: the owner's steps

Montage rule 1175. A push from a person (a chat or group message, a movie night or group invite, a
follow, a reply, a mention, a friend's watch, a Blend invite) now shows their face, as Messages does.
The server side is live once main deploys. The iPhone side needs a new build, and these steps first.

What is already in the repo (ios/Montage/project.yml, regenerated by XcodeGen):

- A new target, `MontageNotificationService` (bundle id `app.montagefilm.Montage.NotificationService`,
  team 5WKL8B8NML, build 21, iOS 17), embedded in the app.
- The app's entitlement `com.apple.developer.usernotifications.communication = true`.
- The app's Info.plist `NSUserActivityTypes: [INSendMessageIntent]`.

## Before the next TestFlight build

1. **Apple Developer, Identifiers, `app.montagefilm.Montage`:** tick **Communication Notifications**
   and save. (Xcode's automatic signing usually does this from the entitlement on the first device
   build; check it is ticked either way. Saving can invalidate the app's current profiles; Xcode makes
   new ones on the next build.)
2. **Regenerate the project:** `cd ios/Montage && xcodegen generate && open Montage.xcodeproj`.
3. **Signing for the new target:** in Xcode, target `MontageNotificationService`, Signing &
   Capabilities, keep **Automatically manage signing** on with the same team. Xcode registers the App
   ID `app.montagefilm.Montage.NotificationService` and its profiles itself. It needs no capability of
   its own (no App Group, no Push). Only if you sign manually: make an App ID with that bundle id and a
   development and an App Store profile for it.
4. **Build number:** raise `CURRENT_PROJECT_VERSION` in all four targets together (rule 863 checks they
   match), then archive and upload as usual.

## Check it on a phone

5. With the new build installed and signed in, have another account send you a chat message with
   your phone locked. You should see their photo (or their initial on their colour, a rounded square)
   beside the notification, their name as the title. Try a group message (the group's name as the
   title), a follow and a movie night invite too.
6. If no face shows: Settings, Montage, Siri & Search, check **Learn from this App** is on (iOS uses
   the donated message for the face), and check step 1 is ticked. If it still does not show, tell the
   next session; the fallback is to add the same entitlement to the extension target too.

Builds from before this one ignore the new fields: their notifications look as they do today.

## Not verified here

- Swift was not compiled (no Xcode in the session). Every line was read by hand.
- How iOS draws the title: the extension assumes iOS replaces the title with the sender's or group's
  name, so for invites, follows and the like it moves the original title to the first line of the
  body. If iOS keeps the title, that line shows twice; tell the next session and it is one flag to
  turn off (`titleInBody` in lib/push-sender.ts).
- The rounded square: iOS crops a notification's face to a circle, so the face is drawn smaller,
  inset on a clear canvas, so the circle never cuts its corners. Whether iOS shows the clear corners
  as clear (not grey) is only visible on a device.
- A group shown as a group: iOS wants more than one recipient; the extension passes you and the
  sender. Check a group message reads as the group.
